## 1. 为什么要补这三艘

现在的俾斯麦叙事弧是断的：

```
丹麦海峡（1941-05-24）  →  追击  →  最终战（1941-05-27）
   4 艘参战舰                13 艘             13 艘
   2 艘可点                                  2 艘可点
```

三场战役合计 24 个参战舰位，只有 9 个挂了 `ship_id`。
补这三艘之后，**丹麦海峡与最终战的每一艘主力舰都能点开**。

| 舰 | 在哪场战役 | 为什么必须补 |
|---|---|---|
| **威尔士亲王号** | 丹麦海峡 | 击伤俾斯麦的那一方；服役不足两个月就出战 |
| **欧根亲王号** | 丹麦海峡 | 俾斯麦唯一的僚舰；全程在场且存活 |
| **罗德尼号** | 最终战 | 实际执行击沉的一方；带队的是它而不是 KGV |

**补完之后丹麦海峡 4/4 全通，最终战的主要战斗舰（2 战列 + 2 重巡）全通。**

**关键判断：威尔士亲王号只写差异字段。**
KGV 级已有 176 条 class fact，威尔士亲王号需要写的只是：

- 身份（建造厂、开工、下水、服役日期）
- **与同级舰的装备差异**（这是同级舰最硬的部分）
- 生命周期节点（服役 → 丹麦海峡 → 远东 → 沉没）
- 状态切片（服役时 / 丹麦海峡时 / 远东时）

⚠️ 但有一个陷阱：**威尔士亲王号是 KGV 级五号舰，1941-05 时还在舾装收尾期**，
它服役时的实际装备状态与首舰英王乔治五世号不同（例如 HACS 火控的配置）。
这部分**必须查证，不能照抄舰级数据**。

## 4. 执行计划（三艘并行，但分片写）

按 `docs/30-new-ship-workflow.md` §5 的 subagent 规则：

```
① 派 3 个 subagent 并行做深度调研
   → 各产出 work/raw/<ship>-tech.md
   → 铁律：每条结论带英文原句 + 来源 URL；区分「未获取」与「0」；
           单列「未获取字段汇总」节；发现任务书前提错了直接反驳

② 主 agent 审阅，决定哪些进 data/、哪些进 narrative、哪些标「未获取」

③ 建 class 文件（欧根、罗德尼需要；威尔士亲王复用 KGV）

④ 写 ships/<id>.yaml（威尔士亲王只写差异）

⑤ 写 slices/<id>.yaml（状态切片）

⑥ 写 articles/<id>.yaml（舰艇正文）

⑦ python scripts/validate.py     必须 0 错误
⑧ python scripts/selftest.py     32 例全过
⑨ build + 部署
```

三个 subagent **各写各的 work/raw 分片**，主 agent 合并。这是 §8.3 的老坑。
