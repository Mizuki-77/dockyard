# 首页侧栏重设计：从「导航副本」到「站内地图」

> 2026-11-22 · 用户提出「把主页面左边的快速索引重新设计一下，不要和上面的导引栏重复了」
> 状态：**已上线**

---

## 1. 问题

旧的 `SideNav` 在首页放了 8 项，其中 **6 项与顶部导航完全重复**：

| 旧侧栏项 | 顶栏是否已有 |
|---|---|
| 主页 | ✅（logo 就是回首页） |
| 战舰信息 | ✅ |
| 海战历史 | ✅ |
| 武器与装备 | ✅ |
| 资料来源 | ✅ |
| 帮助及反馈 | ✅ |
| 俾斯麦号 | ❌ 真正的快捷入口 |
| 俾斯麦级 | ❌ 真正的快捷入口 |

**8 项里 6 项无效。** 而且它是硬编码的：站里已经有 15 艘舰，
侧栏却还只列着俾斯麦一艘，从 2026-11-17 建站起没更新过。

---

## 2. 设计思路

左侧栏的真正优势是**常驻可见**（`position: sticky`），
不是「再做一遍去哪一栏」——那顶栏已经做了。

所以改成回答**「站里有什么、还能往哪钻」**。三条轴：

### ① 舰艇清单（按国家分组）

```
英国 5    胡德 光辉 英王乔治五世 威尔士亲王号 罗德尼号
德国 3    俾斯麦 欧根亲王号 提尔皮茨
日本 4    赤城 加贺 苍龙 飞龙
美国 3    企业号 约克城号 大黄蜂号
```

**全部由 `getShips()` 现算，不硬编码。** 以后加舰自动出现。
国家顺序按本项目的重心排（英→德→日→美），不是字母序。

这条解决了模型玩家最常见的用法：「有没有我要做的那一艘」。

### ② 战役与行动（带参战收录进度）

```
莱茵演习    丹麦海峡海战  4/4
            最终战与沉没  3/13

中途岛作战  中途岛海战    7/7
```

进度数字是**刻意展示缺口**：`3/13` 诚实告诉读者「这场战役还有 10 艘没收录」。
不全的用暖色（`--warn`），全通的用蓝色。

### ③ 按类别浏览（横切入口）

```
航空母舰 8  战列舰 5  战列巡洋舰 1  重巡洋舰 1
→ 按舰种浏览    → 按时代浏览
→ 武器与装备 64 型

雷达 19   舰载机 16   高射炮 12   舰炮 7   火控系统 4
```

舰种与武器类别分布都是现算的。「按舰种 / 按时代」是顶栏没有的二级入口。

## 3. 移动端：折叠抽屉（用户选的 B 方案）

`<1080px` 时：

- 侧栏不再横排成标签（旧的 `flex-wrap` 做法在内容变多后会撑爆）
- 变成一个抽屉：顶部一行「站内地图 ⌄」，点开展开
- 默认收起，避免占满手机首屏
- `localStorage` 记住展开偏好
- **JS 没跑时也不会撑爆首屏**（默认 `display: none`，靠类名展开）

`>1080px` 时：抽屉开关不显示，列表永远展开。

## 4. 顺带修的三处

### 4.1 武器类别缺中文标签

按类别分组时才发现 `weapon.category` 里有三个取值没有 `ENUM_LABEL`：

```
radar        → 雷达
fire_control → 火控系统
aircraft     → 舰载机
```

之前页面会直接把 `radar` / `aircraft` / `fire_control` 三个英文枚举名显示出来。
**这个 bug 不只是首页的问题**，武器页的类别标签也会受影响。

### 4.2 `getWeaponIndex()` 里的强制类型转换

```ts
// 旧：把 ShipFile 冒充 ClassFile，字段恰好同名所以能跑
add(s.id, s.name.zh, 'ship', getEntities(s as unknown as ClassFile).weapons);

// 新：用之前新增的 getShipEntities，语义正确且复用合并逻辑
add(s.id, s.name.zh, 'ship', getShipEntities(s, cls).weapons);
```

顺带删掉一个未使用的 `cls` 变量。验证过：武器总数仍是 64，无变化。

### 4.3 首页统计区去重

原来 6 项里有「艘单舰」「个舰级」，与侧栏重复。改成只留四项：

```
事实记录 / 来源 / 争议记录 / 已注册字段
```

这四项是侧栏给不了的，也是本站区别于普通资料站的地方——
它衡量「能追到出处的数据有多少」。
