# 新舰入库方法论（从 5 舰实测归纳）

> 2026-11-19 · 基于 `data/ships/`（5 舰）+ `data/classes/`（4 级）+ 72 个来源的实测统计
> 数据来自 `work/method_probe.py`、`work/src_probe.py` 的跑分结果，不是拍脑袋。
> **v2（2026-11-19 晚）**：新增 §9 中途岛专项准备、§10 跨国家入坑清单。

---

## 0. 一句话

**新舰不要从零开始。先判断它属于「已有舰级的第 N 艘」还是「全新舰级」，前者只写差异（实测复用比 0.2x–0.6x），后者才走全流程。**

**中途岛这条线是第三种情况：跨国家 + 跨舰种 + 一次 7 艘。** 见 §9。

## 1. 实测出来的三个数字

### 1.1 舰级复用到底省多少（这是最大的一块）

| 舰 | 所属级 | 单舰 fact | 舰级 fact | 单舰/舰级 |
|---|---|---|---|---|
| bismarck | bismarck | 56 | 224 | **0.25x** |
| tirpitz | bismarck | 119 | 224 | **0.53x** |
| illustrious | illustrious | 86 | 151 | 0.57x |
| king-george-v | king-george-v | 67 | 176 | 0.38x |
| hood | admiral | 103 | 37 | **2.78x** |

**怎么读这张表**：

- 俾斯麦级有 224 条舰级 fact，俾斯麦号自己只写了 56 条 → **省掉 75%**。
- 提尔皮茨写了 119 条，因为它改装多、差异大，但**仍然是省掉 47%**。
- **胡德号是唯一反例**（2.78x）：它是一级一舰（海军上将级只有它建成），舰级几乎没数据，全部写在单舰。**这告诉你：一级一舰的船，别指望继承，直接按「全套」估工。**

### 1.2 来源复用率低：25% 才是共享的

72 个来源里，只有 **18 个（25%）** 被 2 艘以上船用到。

**被多舰共用的来源，清一色是两类**：

| 类型 | 例子 | 为什么能共用 |
|---|---|---|
| 同一舰级的站点 | `kbismarck-*` 全部（11 个） | 一个站覆盖整个舰级 |
| 武器专题站 | `navweaps-*`（7 个） | 40 mm Bofors 装在 3 艘船上，一次采完通用 |

**这条的实操含义**：新舰开工时，**先查武器能不能复用**，那是最容易白捡的一块；舰体数据基本要重采。

### 1.3 真正的主力站点只有 5 个

| 域名 | 贡献来源数 | 管什么 |
|---|---|---|
| `kbismarck.com` | 18 | 德国舰（俾斯麦级全套） |
| `navweaps.com` | 16 | **武器，跨国家通用** |
| `hmshood.org.uk` | 14 | 胡德号专站 |
| `armouredcarriers.com` | 13 | 英国装甲航母 |
| `navypedia.org` | 4 | 快速拿主尺度/排水量的骨架 |

**结论：德国舰看 kbismarck，武器一律看 navweaps，英国舰看各自的专题站，navypedia 只用来垫底核对。**

## 2. 五舰暴露的「字段套路」

统计每类字段在 5 舰里的命中次数，能看出哪些是**必填项**、哪些是**这舰本来就没有**。

### 2.1 五舰全有的字段（新舰必须搞到，否则一眼看出缺）

| 组 | 5/5 全覆盖的字段 |
|---|---|
| identity | name_original / name_zh / name_en / operator / ship_type / nation / era / building_program |
| dimensions | displacement.standard / length.oa / beam.wl / draught.mean |
| propulsion | plant_type / shafts / boiler.count / boiler.type / turbine.count / turbine.type / power.design / speed.design / fuel.capacity |
| construction | builder / builder_location / laid_down / launched / commissioned / fate_date |
| protection | scheme / armor.thickness / armor.weight / underwater.depth |
| service | complement.standard / fate_category |
| aviation | aircraft.types（连战列舰都有水上飞机） |

**这 35 个字段是骨架。** 新舰只要这 35 个拿齐，页面就是完整的；缺一个，页面上会出现「未记载」，读者一眼能看出是没查完。

### 2.2 命中率低的字段 —— 不是漏采，是船型差异

| 字段 | 命中 | 原因 |
|---|---|---|
| `aviation.deck.length` / `hangar.*` / `elevator.*` | **1/5** | 只有航母有 |
| `armament.aa_20mm.count` | 1/5 | 只有提尔皮茨逐期记了；其他船只在截图里能数 |
| `armament.broadside_weight` | 2/5 | 需要来源自己给，不能自己乘 |

**判据：先问「这个字段在这类船上是否成立」，再问「我查到没有」。** 战列舰没有机库，那不是未获取，是字段不适用。

### 2.3 装甲字段的坑

`protection.armor.thickness` 5/5 全覆盖，但它**是带 `qual` 的字段**——必须注明是舷侧带、甲板、炮塔还是司令塔。裸写一个厚度等于没说。

## 3. 两种开工路径

### 路径 A：已有舰级的第 N 艘（省 50%–75%）

以「同级的 KGV 级再造一艘（如 Prince of Wales）」为例：

1. **先读舰级文件**，把 224 条 fact 看一遍——这已经是 75% 的数据。
2. **只写差异**：逐舰不同的只有这几类：
   - 建造日期（开工/下水/服役/结局）
   - 改装历程（这条最容易漏，提尔皮茨的 119 条里一半是改装）
   - 战历相关（参与过哪场战斗 → 影响涂装、损伤、编制）
   - 单舰覆盖值（如提尔皮茨满载吃水 10.61 vs 俾斯麦 10.55）
3. **切片单独写**：`data/slices/<id>.yaml` 不继承，因为同级舰改装节奏不同。
4. **正文单独写**：`data/articles/<id>.yaml`（这个不省，每艘都是独立叙事）。

**验收标准**：`python scripts/validate.py` 通过，且单舰 fact 数在 50–120 之间。低于 50 要怀疑是不是漏了改装；高于 150 要怀疑是不是把舰级数据抄进来了。

### 路径 B：全新舰级（走全流程）

1. **定级**：这艘船是独立舰级还是属于某级？（胡德的教训：一级一舰也要建 class 文件，只是内容少）
2. **派 subagent 调研**（规矩见 §5）
3. **写舰级文件**：公共数据全进 `classes/<id>.yaml`
4. **写单舰文件**：只写差异
5. **切片 + 正文 + 配图**
6. **跑 validate + build**

**工作量参考**：5 舰实测单舰 56–119 条 fact、来源 11–15 个、切片 5–9 个。

## 4. 按船型复用的「字段清单模板」

不要再从 196 个字段里挑，直接按这四类套：

### 4.1 战列舰 / 战列巡洋舰（俾斯麦、提尔皮茨、KGV、胡德）

必查 35 个骨架字段 + 这些重点：
- `protection.armor.thickness`（按部位分多条：舷侧/甲板/炮塔/司令塔/舵机）
- `armament.broadside_weight`（来源给才算）
- `aviation.catapult.count` + `aircraft.capacity`（水上飞机）
- `sensors.radar.installed`（多值，每型一条，`multi: true`）

### 4.2 航空母舰（光辉级）

在上面基础上替换：
- 删掉 `protection.armor.thickness` 的炮塔项，改成飞行甲板装甲
- 新增 `aviation.deck.*` / `hangar.*` / `elevator.*` / `arrestor.count`
- **`aviation.hangar.height` 是装甲航母的核心数字**（机库越矮，能塞的飞机越小）
- `aviation.fuel.volume` 优先于 `aviation.fuel.capacity`（来源只给体积，换重量是推断）

### 4.3 一级一舰的船（胡德）

- **不指望继承**，按全套估工（2.78x 那个反例）
- 舰级文件仍要建，但只放"本级的定义性数据"（设计指标、装甲方案）
- 特别注意：这类船往往改装史极长，切片要多

### 4.4 通用：三种口径必须分开记

五舰里踩过的坑，新舰一定会再遇到：

| 口径 | 例子 | 怎么处理 |
|---|---|---|
| **排水量** | 标准 / 满载 / 深载 / 公制 Typverdrängung | 四个字段分开，不合并 |
| **长度** | 全长 / 水线长 / 垂线间长 / 甲板长 | 四个字段分开；航母特别注意「飞行甲板长 ≠ 船体全长」 |
| **航速** | 设计 / 试航实测 / 最大 / 巡航 | 四个字段分开 |

**来源自己没写清口径的，标 `comparable: false`**，不要硬塞进标准口径。

## 5. subagent 调研任务书模板（血泪版）

从 S1/S2 的实践里提炼，直接抄：

```
你是战舰资料检索员。任务：为 <舰名>（<舷号>）采集技术数据。

## 硬规矩（违反任一，整份作废）
1. 每条数值必须附**英文原句**（原文照抄，不要翻译后回译）+ 来源 URL。
2. **查不到就写「未获取」**，绝对不许推算、不许跨来源拼凑、不许按同级舰类推。
3. 区分「未获取」和「0」——KGV 真没鱼雷管，那是 0；查不到是多少，那是未获取。
4. 有分歧的地方**单列一节**，写清两边各说什么、各引哪句原话，不要自己裁决。
5. 如果发现任务书里的前提是错的，**直接反驳**，附原话。

## 输出格式
- 按 §0 身份 / §1 建造 / §2 主尺度 / §3 排水量 / §4 动力 / §5 防护 /
  §6 航空 / §7 武备 / §8 雷达火控 / §9 编制 / §10 涂装 / §11 生涯时间线 /
  §12 抓取失败清单 / §13 来源→URL 对照表 / §14 未获取字段汇总
- 每个数值一行，附原句与 URL
- 最后必须给「未获取字段汇总」，没这一节视为没做完

## 字段范围
（把 §4 对应船型的字段清单粘进来）
```

**并发写文件的坑**（S2 踩过）：多个 subagent 同时写同一个大文件会互相覆盖。让每个 agent 写**独立分片**（`work/imgfrag/img-radar.yaml`），主会话用脚本合并。

## 6. 开工前的 30 秒检查清单

新舰开工前问自己：

1. **它是哪个舰级的？** 已有级 → 路径 A；没有 → 路径 B
2. **它的武器能不能复用现有 `weapon:*` 实体？** 先查 `getWeaponIndex()`，能复用就省一大块
3. **它有没有一级一舰的特征？** 有 → 按全套估工
4. **它是航母还是战列舰？** 决定字段清单
5. **navypedia 上有没有它的骨架数据？** 有 → 先拿骨架垫底，再逐项找专题站核实

## 8. 还没验证的部分

诚实地标出来：

- **样本只有 5 艘，且 3 艘是德国/英国主力舰**。日本、美国、意大利舰的字段分布可能不同（比如 USN 的雷达型号体系、IJN 的弹药基数口径）。
- **航母只有 1 艘**（光辉级），`aviation.*` 的「必填项」判断样本不足。
- **复用比 0.25x–0.6x 是德国战列舰级的数据**，换到驱逐舰级（动辄十几艘同级）可能更极端。

**建议**：第 6、7 艘船（最好挑一个非英德的、或一艘驱逐舰）入库时，回头校正这份文档。

**中途岛正好是这个建议的完美样本**——见 §9，它能一次性验证「跨国家 + 驱逐舰 + 多艘同级」三件事。

## 9. 中途岛专项准备（2026-11-19 晚开工）

### 9.1 为什么它跟前面 5 舰都不一样

| 维度 | 现 5 舰 | 中途岛 |
|---|---|---|
| 国家 | 德 / 英 | **日本 / 美国**（全新，零积累） |
| 舰种 | 战列舰 3 + 战巡 1 + 航母 1 | **航母 4 + 航母 3**（航母首次成规模） |
| 同批艘数 | 每次 1 艘 | **7 艘同时**（赤城/加贺/苍龙/飞龙 + 企业/约克城/大黄蜂） |
| 舰级复用 | 俾斯麦级省 75% | **赤城、加贺不是同一级**（分属不同设计来源）；约克城级 3 艘才真能复用 |
| 来源 | kbismarck/navweaps/hmshood | **全新一批**（IJN 看 combinedfleet / JACAR，USN 看 NHHC / DANFS） |

**最关键的一条：赤城和加贺不是同级。** 赤城是天城级战巡改航母，加贺是加贺级战列舰改航母——两艘船出身完全不同，加贺的舰体甚至是长门级的底子。**别按「赤城级 2 艘」处理，那样会把 30% 的差异抹平。**

同理约克城级三艘：约克城、企业、大黄蜂确实是同一级，**这三艘才是真能走路径 A 的**。

### 9.2 需要先补的字段（已补 2 个）

| 字段 | 状态 | 为什么必须要 |
|---|---|---|
| `armament.aa_25mm.count` | ✅ **已补** | 日本海军没有 20 mm，主轻高炮是九六式 25 mm。原来只有 `aa_20mm.count`，赤城/加贺的防空火力无处可记 |
| `armament.aa_40mm.count` | ✅ **已补** | 美军航母 40 mm Bofors 是主力中程防空，原来完全没字段 |
| `aviation.hangar.*` | 已有 | 中途岛航母的机库是核心数据（赤城三层甲板 vs 美舰单层大机库，设计哲学差异巨大） |
| `aviation.deck.*` | 已有 | 赤城/加贺的飞行甲板长度是改装史的直接证据 |
| `sensors.radar.installed` | 已有，`multi:true` | **中途岛的关键差异**：日军雷达极落后，赤城沉没时基本无雷达；美军已有 CXAM |

### 9.3 中途岛这批的「必查但容易漏」

现 5 舰的 35 个骨架字段照旧，但航母有这些特殊项：

| 项目 | 为什么中途岛必须查 |
|---|---|
| **机库层数与尺寸** | 赤城三层甲板 vs 美舰单层，这是设计哲学的核心对比 |
| **飞行甲板长度** | 赤城/加贺改装后从战巡/战列舰底子来，甲板比例和纯血航母不同 |
| **升降机数量与位置** | 影响出动率的硬指标 |
| **拦阻索** | 中途岛回收作业的关键 |
| **舰载机编制（机型+数量）** | 日军零战/九九舰爆/九七舰攻；美军 F4F/SBD/TBD。**TBD 鱼雷机几乎全灭**是战役关键 |
| **雷达有无与型号** | 日无 / 美有 CXAM，这直接决定了先发现对方 |
| **防空炮口径构成** | 25 mm（日）vs 40 mm+20 mm（美），火力密度差一个量级 |
| **舰桥/舰岛位置** | 赤城左舷舰岛（罕见设计，实验性） |

### 9.4 来源路线（全新，与现 5 舰不重叠）

| 国家 | 主要来源类型 | 说明 |
|---|---|---|
| 日本 | `combinedfleet.com`（TROM 表格，逐日记录）、JACAR（亚洲历史资料中心，一手档案）、日本 Wikipedia 的日文原始资料 | combinedfleet 的 TROM 格式在 `work/raw/field-design-refs.md` 里已经分析过，**当时就记了「对我们时间轴设计特别有参考价值」** |
| 美国 | `NHHC`（海军历史与遗产司令部）、`DANFS`（美国海军战舰辞典）、`NavSource` | DANFS 是官方舰史，层级接近 B |

**注意**：这两批来源的 tier 判定要重做。DANFS 是官方出版物（B 级），combinedfleet 是专题站（D 级）。

### 9.5 建议的分批（7 艘不要一次全上）

| 批 | 内容 | 理由 |
|---|---|---|
| **首批** | 赤城 + 企业号 | 各一国的旗舰，把两套字段清单跑通。赤城验证「改装航母」，企业验证「纯血航母 + 约克城级继承」 |
| **次批** | 加贺 + 约克城 | 加贺验证「不同舰级」（不能按赤城级套）；约克城直接继承企业号的舰级数据 |
| **三批** | 苍龙 + 飞龙 + 大黄蜂 | 苍龙/飞龙是同级但设计中途改过；大黄蜂继承约克城级 |

**先 2 艘再 2 艘再 3 艘。** 理由是：第一批会暴露字段缺口（比如「航空弹药储量怎么记」），改完字段再上第二批，比 7 艘一起返工便宜得多。

### 9.6 战役页本身

`data/battles/` 现在只有 2 场（丹麦海峡、最后一战），都是 `theater: atlantic`。

中途岛要新建 `data/battles/midway.yaml`，`theater: pacific`——**这是本站第一个太平洋海区**，海战左树会自动多出一个「太平洋」分支。

`data/operations/` 现在只有 `rheinubung`。中途岛是一次行动包含侦察、空袭、航母对决多个阶段，**适合做成 operation + 多场 battle**（跟莱茵演习的结构一样：一条线里分开讲）。

## 10. 跨国家入库的坑（写给下一次的自己）

1. **别照抄德/英的字段习惯。** 德国人写 Typverdrängung，日本人写「公試排水量」，美国人写 standard/full load——三种口径体系，硬套会错。
2. **命名单位要按原产国习惯给型号名。** 日本「九六式二十五粍三連装機銃」，美国「40 mm/56 Bofors」——型号名本身是信息，不要统一翻译掉。
3. **一舰一档案，但同级要真复用。** 约克城级三艘能复用 60%+；赤城和加贺不能（不同级）。
4. **雷达是相对实力的硬指标。** 中途岛日军几乎无雷达、美军有 CXAM，这个差异比火炮数字更决定胜负，页面要能一眼看出来。
5. **多艘同时做时，subagent 必须各写独立分片文件**（S2 踩过覆盖的坑），主会话用脚本合并。
