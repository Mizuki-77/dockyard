## 3. 关键技术教训

### 3.1 Commons 分类名的命名规律（硬知识）

这一轮花了不少时间在猜分类名上。总结出的规律：

| 国家 | 模式 | 例 |
|---|---|---|
| 美国 | `USS <名> (<舷号>)` | `USS Enterprise (CV-6)` |
| 英国 | `HMS <名> (<舷号>)` 或 `HMS <名> (ship, <下水年>)` | `HMS Hood (ship, 1920)` |
| 日本 | `<名> (ship, <下水年>)`，罗马字带长音符号 | `Sōryū (ship, 1937)` |
| 德国 | `<名> (ship, <下水年>)` | `Tirpitz (ship, 1941)` |

**容易踩的坑**：
- `HMS Hood (51)` 是 0 个文件，正确的是 `HMS Hood (ship, 1920)`（51 是舷号但不是分类名）
- `HMS Prince of Wales (1941)` 是 0，正确是 `(ship, 1941)`
- `Bismarck (ship, 1939)`、`Prinz Eugen (ship, 1938)` ✓，但 `Tirpitz (ship, 1939)` 错，是 `(ship, 1941)`
- 同名现代舰会混进分类：`illustrious` 分类里有 `R06`（现代航母）、`king-george-v` 有 `(1911)`（一战前战列舰）

**判断方法**：先用 `list=search` 搜 Category 命名空间，再用 `list=allpages&apprefix` 列同前缀分类，最后用 `categorymembers` 数文件数确认。

### 3.2 必须校验文件头，否则会把 HTML 错误页当图片

**这是本轮最大的技术坑。**

第一批 180 张下载完后，抽查文件大小时发现两张只有 17KB / 43KB。深挖发现：
**44 张文件的实际内容是 HTML 错误页**，文件头是 `<!` 而不是 JPEG 的 `\xff\xd8`。

原因：Commons 限流时返回的是 HTML 错误页，`urlopen` 不抛异常（HTTP 200 也可能是错误页），
`r.read()` 拿到 HTML 就写进文件了。

**修复**：下载后必须检查 `data[:2] == b'\xff\xd8'`，不是就重试或换图。

```python
if len(data) > 5000 and data[:2] == b'\xff\xd8':
    write(data)   # 才是真图片
```

同理，**视频文件（.ogv）也会被当成图片下载**。标题里带 `.ogv` / `.webm` 的必须排除。

### 3.3 自动筛选一定会混进错图，必须人工复核

自动规则（关键词黑名单 + 评分排序）仍然放进了这些：

| 舰 | 错图 | 原因 |
|---|---|---|
| 约克城 | 列克星敦号爆炸照 | 分类里有同场战斗的其他舰 |
| 约克城 | 四舰合影 | 主体不是本舰 |
| 胡德 | 同一张 1924 年照片的 4 个修复版本 | 文件名不同但内容同 |
| 威尔士亲王 | 丘吉尔人物照 | 分类里有舰上人物照 |
| 俾斯麦 | 希特勒照片、纳粹旗、纪念牌 | 分类里混入历史人物与纪念物 |
| 企业号 | 1953 年封存基地航拍 | 分类里有退役后照片 |

**结论：黑名单能挡掉 90%，剩下 10% 只能人眼过。** 每一批都要 dump 出标题+描述核对。
