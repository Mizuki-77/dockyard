## 2. 三条红线（违反即废掉整个项目的价值）

### 2.1 有争议的说法一条都不删

被否定的说法要留在 `note` 或进 `narrative`，因为下一代研究者会重新拿它出来。删掉等于把网站的寿命锁在今天的认知水平上。

**实践中怎么落地**：两个来源打架就两条都留，`note` 里写「两说并列，不裁决」。

**现收录的活例子**：
- 胡德号 Type 284 装成日：协会记 03-15、年表记 03-17，两个日期都写在正文里
- 加贺 25mm 高炮：11 基 vs 14 基，官方图纸未存，两说并存
- 赤城沉没方式：鱼雷处分说 vs 大爆炸致沉说
- 加贺沉没：萩风鱼雷处分 vs 日文维基「大爆炸致沉」
- 苍龙战死者：718 vs 711

### 2.2 推断值不进 `data/`

无法直接溯源到来源的值，只记可溯源的布尔事实；推算过程留 `work/`。

**现收录的活例子**：
- 33 个雷达/火控/舰载机实体**全都没有 `weapon.in_service_from`**——不是漏了，是查不到型号首服役年
- 日本三型舰载机的**最大速度与航程未写入**——报告没给完整数值
- 赤城/加贺的**最大吃水未获取**——所有来源只给单一「吃水」值

### 2.3 fact 的 `field` 必须在注册表里；`valid` 时间窗 + 至少一个 `src` 必填

缺任何一项，`validate.py` 直接报错。`src` 引用的 id 必须在 `sources.yaml` 登记过，且 **tier E（百科）不能作 fact 来源**。

### 2.4 两条新增的硬约束（本轮加入）

**`confidence` 只有 A/B/C，没有 D。** D 是**来源 tier**（见 `sources.yaml`），不是置信度。
这个错本轮犯了 **5 次**（akagi / enterprise / soryu / kaga / 各一遍）。校验器现在对 `confidence: D` 有专门提示。

**`comparable: false`** —— 来源自己承认口径对不上时用它，对比器不拿它排高低。标了必须写 `note`，否则报错。

## 3. 数据模型（整个项目的地基）

### 3.1 实体分层

| 层 | 实体 | 说明 |
|---|---|---|
| 1 | `class` | 舰级。公共数据（设计指标、装甲方案、武备布置） |
| 2 | `ship` | 单舰。身份 + 生命周期节点 + **差异数据** |
| 3 | `fact` | 一条带时间窗和来源的数据点 |
| 4 | `narrative` | 一段有争议的叙述（多说法并列） |
| 5 | `weapon` / `mount` / `image` / `battle` | 独立实体，id 互相引用 |

### 3.2 fact 的骨架

```yaml
- field: displacement.standard      # 必须来自 data/fields.yaml
  value: 41700
  unit: t
  src: [kbismarck-bsweights]        # 至少一个，必须已登记
  valid: { from: 1940-08-24, to: 1941-05-27 }   # 时间窗必填
  confidence: A                     # A / B / C
  note: 德方标准排水量口径
  about: weapon:38cm-sk-c34         # 可选：指明归属实体
  qual: { shell_type: apc }         # 可选：限定词
  comparable: false                 # 可选：口径不可比，不进对比器高低判定
```

### 3.3 舰级继承与单舰覆盖

**同级舰公共数据写在 class 上，单舰只写差异。** 解析顺序（同一时刻、同一字段）：
单舰 fact 命中即覆盖舰级，**不与舰级值构成分歧**。

**实测复用比**（见 `docs/30-new-ship-workflow.md`）：俾斯麦级省 75%、KGV 级省 62%。

### 3.4 主值规则

```
1. 证据层级高者优先（A > B > C > D，E 不参与）
2. 层同：口径明确者优先
3. 层同、口径同：采集时间新者优先
4. 仍平：按 source id 字母序（保证构建可复现）
```

主值**不是裁决结果**，是「默认我先给你看哪个」。

### 3.5 证据层级

| 档 | 内容 | 能否作 fact src |
|---|---|---|
| A | 一手档案（战争日志、脱险报告、审问记录） | ✅ |
| B | 同期官方出版物（Jane's、海军部手册、官方舰史） | ✅ |
| C | 权威二次文献（Conway's、Campbell、NavWeaps） | ✅ |
| D | 专题网站（KBismarck、Navypedia、combinedfleet） | ✅ |
| E | 百科（维基） | ❌ **只能找线索** |

**当前来源构成**：A 67 / B 15 / C 40 / D 92 / E 8 = 222 条。

## 6. 本轮新增的机制（最容易被后人改坏的部分）

### 6.1 对比器（P3）

`buildCompareIndex()` 在 `src/lib/data.ts`，预生成约 50 KB 内联 JSON。三个非显然项：

1. **`deps` 必须序列化进 payload** —— `pickPrimary()` 在浏览器里需要 `tierOf` / `fetchedOf`，构建期对象无法传过去。漏了这一步，主值规则当场退化成「取第一条」。
2. **索引阶段不能照抄「单舰层有值就只用单舰层」** —— 那条规则对「整条生命取一个主值」是对的，对**按时刻查询**是错的。必须全量带上，交给浏览器按 t 过滤。
3. **命中多条时间窗 ≠ 分歧** —— tirpitz 编制 1941 起 2,065 + 1943 起 2,608，两条都 open-ended，1943 年后两条都命中。那是时序演进。

### 6.2 `comparable: false`

口径对不上时不进对比器高低判定。当前 4 条：

| 舰 | 字段 | 为什么 |
|---|---|---|
| hood | `displacement.standard` | navypedia 自己写 "normal" |
| illustrious | `dimensions.length.oa` | 很可能是飞行甲板长 |
| king-george-v | `aviation.aircraft.capacity` | 数是水上飞机，光辉级那栏是舰载机编制 |
| tirpitz | `aviation.aircraft.capacity` | 极限搭载（4 在库 + 2 在弹射器） |

### 6.3 事件流详略切换

`BattleEvent.major?: boolean` + 页面按钮 + localStorage。**中途岛 9 条 major / 85 条总**。

### 6.4 三段式飞行甲板字段

`aviation.deck.upper/middle/lower.length` —— 用单一 `deck.length` 表达不了。

**赤城**：上段 190.20 / 中段 **15.0** / 下段 55.02 m
**加贺**：上段 171.30 / 中段 **15.0** / 下段 55.02 m

那个 15 m 是设计失败的直接证据——放进「249 m 全通甲板」里就看不见了。

### 6.5 航空器字段（10 个）

注册表原来**只有炮的字段**，没有任何能描述飞机的字段。本轮补：

`weapon.aircraft.span / length / height / empty_weight / gross_weight / max_speed / range / crew / engine / power`

### 6.6 切片配图（`sliceImages()`）

| 优先级 | 规则 | `how` 标记 |
|---|---|---|
| 1 | 切片里显式写了 `image: <id>` | `explicit` |
| 2 | 照片 `date` 落在切片时间窗内 | `in_range` |
| 3 | 窗外最近一张，且间隔 **≤ 365 天** | `nearest` |
| 4 | 都没有 | `none` → 显示「该时期无影像」 |

**阈值 365 天**：初版设 3 年，实测把 KGV 1942 年切片挂上了 1945-08 日本投降的合影。

## 7. 图片体系与授权

### 7.1 授权三档

| 档 | 条件 | 处理 |
|---|---|---|
| **A · 归档** | PD / CC0 | 下载到本地；记录机构 + 藏品号 + 许可 + 获取日 |
| **B · 外链** | CC-BY / CC-BY-SA；或授权待确认 | 只放链接与缩略图；有署名义务的强制渲染署名 |
| **C · 禁用** | IWM 全站、大和ミュージアム、Europeana NoC-NC、一切 "Editorial use only" | 不出现 |

**当前分布：A 242 / B 28 / C 0。**

### 7.2 三条硬约束

1. **授权跟着「这张具体的数字化副本」走**，不跟着「这个历史事件」走。
2. **IWM 的「非商业」卡的是本站商业模式。** 本站已定**无广告、无打赏、无周边**（2026-11-17 拍板），故 IWM 可作 B 档；**一旦变现必须重新评估**。
3. **Bundesarchiv 不得整库标 CC-BY-SA 3.0 de。**

### 7.3 IWM 判例

| 情况 | 档位 | 理由 |
|---|---|---|
| 原件藏 IWM、Commons 副本标 Public domain | **A · 归档** | 授权跟副本走 |
| 从 IWM 站内直接下载的副本 | **B · 外链** | 受 Non-Commercial Licence 约束 |
| Commons 上无 PD 依据 | **C · 禁用** | 不赌 |

### 7.4 图片来源的技术要点（本轮踩过的坑）

- **缩略图宽度只允许** 120 / 250 / 330 / 500 / 960 / 1280 / 1920 / 3840。本站习惯 1280。
- **Commons 对本站持续 429**：每张图之间 sleep 2-3 秒，遇 429 等 10-20 秒重试。一次抓 10 张以上几乎必被限流。
- **绝对不要用关键词搜索抓图。** 本轮踩了三次：抓到过图书馆藏书封面、《1904 年维多利亚日报》、现代美国空军合影。
  **正确做法：按 Commons 分类浏览**（`Category:Japanese aircraft carrier Akagi` 这类），分类里的主题不会错。
- **Commons 的 `Artist` 字段本身就是 HTML 片段**。写进 `images.yaml` 前必须剥标签，否则页面会渲染出 `<div class="fn value">`。
- 国内**必须**走代理 `http://127.0.0.1:7897`。

## 8. 工作流程（怎么继续生产内容）

### 8.1 已跑顺的流水线

```
① 派 subagent 做单一主题的深度调研
   → 产出 work/raw/<topic>.md（带每个数值的英文原句 + 来源 URL + 争议标注）
② 主 agent 审阅，决定哪些进 data/、哪些进 narrative、哪些标「未获取」
③ 改 data/*.yaml
④ python scripts/validate.py      （必须 0 错误）
⑤ python scripts/selftest.py      （32 例全过）
⑥ cmd /c "npm.cmd run dev" 本地看效果
⑦ cmd /c "npm.cmd run deploy"
```

### 8.2 subagent 调研的铁律

完整模板在 `docs/30-new-ship-workflow.md` §5。核心五条：

1. **只给主题，不给答案。** 要求每条结论带**英文原句**，并能反驳任务书前提。
2. **明确要求区分「未获取」和「0」。**
3. **要求登记 `src`，并对分歧单列。**
4. **发现前提错了直接反驳。**
5. **单列「未获取字段汇总」节**，没这一节视为没做完。

**本轮被 subagent 纠正了 12 处错误**（详见 `docs/32-midway-progress.md` §4）。**这是正常的，subagent 纠错比顺着写有价值。**

### 8.3 并发 subagent 的写文件冲突

多个 subagent 同时写同一个大文件会互相覆盖。**解法**：让每个 agent 写**独立分片**，主会话用脚本合并。

### 8.4 新增一艘单舰的步骤

见 `docs/30-new-ship-workflow.md`。摘要：先判断是「已有舰级的第 N 艘」（省 50-75%）还是「全新舰级」；已有级只写差异字段。

## 10. 环境与命令（Windows 专用坑）

### 10.1 命令

```powershell
cmd /c "npm.cmd run dev"        # 本地开发 :4321
python scripts/validate.py      # 全量校验
python scripts/validate.py --ship akagi   # 只查单舰
python scripts/selftest.py      # 32 例自测
cmd /c "npm.cmd run build"
cmd /c "npm.cmd run deploy"     # 需先开代理
```

> **PowerShell 里必须走 `npm.cmd`**，直接敲 `npm` 会撞执行策略（`npm.ps1` 被禁）。

### 10.2 本轮踩到的坑（按痛感排序）

1. **`confidence: D` 是错的。** D 是来源 tier，不是置信度。本轮犯了 5 次。校验器现在有专门提示。
2. **YAML 里 `zh: >-` 折叠块后面跟 `src:` 会把它吞进 `zh`。** `src:` 必须与 `text:` 同级（8 空格），不能与 `zh:` 同级（10 空格）。本轮犯了 4 次。
3. **`**加粗**` 在 YAML 里会被当别名报错，在页面里也不渲染。全站正文都不要用 markdown 加粗。**
4. **`heading` 是字符串不是 BiText。** 写成 `{zh:.., en:..}` 会渲染成 `[object Object]`。
5. **模板里硬拼「号」字**：`${name.zh}号` 遇到「企业号」会变成「企业号号」。已改成 `displayName` 按需判断。
6. **关键词搜索抓图会抓到垃圾**（图书馆封面、1904 年报纸、现代空军合影）。必须用 Commons 分类浏览。
7. **Commons 的 `Artist` 字段带 HTML**，写进 yaml 前必须剥标签。
8. **`edit` 报 `ReplaceFileW EIO (Win32 1175)`** = dev server 锁了文件句柄。**先停 dev 再改**；同一文件连续两次失败就说明是占用，**不要重试第三次**。
9. **PowerShell 里 `python -c "..."` 带中文或嵌套引号极易被拆碎**。**超过两行的 python 一律写成 `work/*.py` 文件再跑。**
10. **PowerShell 里 `Get-Item 'src\pages\ships\[id].astro'` 会返回 0 字节**——`[id]` 被当通配符。用 `-LiteralPath`。
11. **PowerShell 重定向输出是 UTF-16**，Python 读会崩。用 Python 的 `io.open(..., 'w', encoding='utf-8')` 写文件。
12. **dev server 会锁 `data/` 与 `src/`**，改文件前必须停。

### 10.3 网络

## 11. 用户沟通习惯（影响交付方式）

- **先给结论，但要能追到推导。** 不要「应该」「大概」，不确定就直说并给验证方式。
- **大工程先报价**（token / 时间）再动手。
- **需求变更是常态，不是返工。**
- **不确定就问一句**，不要替他扩大需求、不要脑补。
- 改动超过 3 个文件、或要删除/覆盖已有文件，**先说一声**。
- 一件事做完就停，不要顺手把旁边的也重构一遍。
- 长内容落盘成 `.md`，不要把几十行正文铺在聊天里。
- **他给的草图/截图就是需求。**
- **每次做完要主动给网址**，他要自己点开看。
- **dev server 用完要问关不关**——曾经一个空转 9 小时的 server 导致电脑没能自动关机。

## 12. 快速上手清单

新接手的人，按这个顺序：

1. **跑一次 `python scripts/validate.py`**，确认现在是绿的
2. 读 `docs/00-framework.md`（401 行）—— 设计决策的原始理由
3. 读 `docs/32-midway-progress.md` —— 最近一轮做了什么、被纠正了哪些错
4. 读 `docs/30-new-ship-workflow.md` —— 加新舰的方法论与复用比实测
5. 看 `data/ships/tirpitz.yaml` —— 单舰只写差异的范例
6. 看 `data/ships/akagi.yaml` —— 有武器关联、有三段甲板、口径争议标注最全的范例
7. 看 `src/lib/catalog.ts` 与 `src/lib/tree.ts` —— 「本站分类」层
8. 想加新舰：按 `docs/30-new-ship-workflow.md` 走
9. 想改界面：先看 `CatalogTree.astro`（两栏目共用）与 `global.css`

**这个项目最容易被做坏的地方**：
- 为了赶进度把「查不到」写成推测值。**这网站的整个价值建立在「每条数据都能点开看来源」上**。
- 为了页面好看把有争议的说法删掉。
- 把推断的分类（主炮/副炮/防空炮）写进 `data/` 当 fact。
- 把 B 档图当 A 档塞进 `public/img/`。上线前必须逐张核 license。
- **凭记忆填数据。** 本轮标 `major` 时凭印象写时刻，4 条里时刻对、内容错。**必须回原文核对。**
