用户给的两张草图（海战历史 / 武器与装备）统一是「左树 + 右文」。落地结果：

| 页面 | 左树结构 | 右侧 |
|---|---|---|

### 2.3 数据层的三个扩展

1. **`BattleFile.theater`** —— 海区字段（`atlantic` / `north_sea` / `mediterranean` / `indian_ocean` / `pacific` / `arctic` / `baltic` / `other`）。
   `validate.py` 加了枚举校验，拼错直接报错——**不能从 `location` 文本里猜海区**（那是给人读的一句话，当分组键会把同一片海切碎）。
2. **`weapon.category` 枚举扩了三值** —— `radar` / `fire_control` / `aircraft`。此前雷达与舰载机只是 `sensors.*` / `aviation.*` 字段，不是实体。
3. **`Slice.image`** —— 手工指定切片配图（可选）。不给就走自动匹配。

### 2.4 时间轴切片配图（用户明确要求）

`src/lib/data.ts` 新增 `sliceImages(shipId, slices)`：

| 优先级 | 规则 | `how` 标记 |
|---|---|---|
| 1 | 切片里显式写了 `image: <id>` | `explicit` |
| 2 | 照片日期落在切片时间窗内（primary → A 档 → 距窗起点最近） | `in_range` |
| 3 | 窗外最近一张，且间隔 **≤ 365 天** | `nearest` |
| 4 | 都没有 | `none` → 页面显示「该时期无影像」 |

**阈值为什么是 365 天**：初版设 3 年，实测把 KGV 1942 年切片挂上了 1945-08 日本投降的合影——那两天舰上多了一整套雷达和防空平台，外形差得远。宁可不显示，也不要让模型制作者照着错的照片改模型。

切片失败时的行为是**显式隐藏大图**，不能留着上一片的老图（否则读者会以为 1955 年退役时舰还是 1940 年那个样子）。

## 3. 关键设计决策（别再重新争论）

### 3.1 「主炮 / 副炮 / 防空炮」不进 `data/`

这是**本站给模型制作者做的检索分类**，不是史料字段。皇家海军自己的文件里只说 `secondary armament` 或 `HA/LA mounting`，没有「role」栏。写成 fact 就等于把本站推断塞进数据层，违反第二条红线。

所以 `data/` 只留 `weapon.category`（有出处的粗类），`src/lib/catalog.ts` 负责把「粗类 + 型号」映射成树上的位置。页面明确标注「分类：本站归并」。

### 3.2 同一型武器的多来源参数**不合并**

同一型 20 mm Oerlikon 在光辉级里记弹重 0.123 kg、在 KGV 级里记 0.12 kg。武器详情页按来源分块并列显示，**不合成一张表**——合并就必须挑一个值，那等于替来源做裁决。合并数值是 `data/` 里 narrative 的活，不是页面该干的。

`getWeaponIndex()` 只合并「这一型装过哪些舰」，不合并数值。

### 3.3 重复实体是错误，不是冗余备份

`illustrious` 曾有 `weapon:40mm-bofors`（舰级）与 `weapon:4in-bofors`（单舰）两份记录，描述的是同一批炮（都 3 座、都 1944-10）。结果是左树上出现两门一模一样的 40 mm Bofors。已归并到舰级那份（信息更全），单舰那份删掉并在原位留注释说明归并方向与「不要为了保险加回来」。

### 3.4 IWM 判例

原件藏 IWM 的英国战时官方摄影、Commons 副本标 PD（Crown Copyright 已过期）→ **A 档归档**，note 必须写 IWM 编号 + 「IWM 官网对其网站副本另有非商业条款，本站引用的是 Commons 的公有领域版本」。
IWM 站内直接取得、或 Commons 上无 PD 依据的 → **C 档禁用**。

依据 §5.4 硬约束 1「授权跟这张具体的数字化副本走」。**残留风险已知**：Commons 的 PD 标签是社区标注不是担保。

## 7. 血泪教训（写代码时别重复）

1. **流式映射写 title 会静默坏数据**。`title: { zh: ..., en: ..., 1939 }` —— `en` 句子里的逗号被 YAML 当键值分隔符，后半句变成垃圾键。有 15 条这么坏的，而且是「解析成功」的坏（不报错，只是多一个 `1939: null` 键）。**给 subagent 的范本必须用块式 title。**
2. **`yaml.dump` 会丢掉文件头的注释**。`data/images.yaml` 顶部 10 行是授权规则与 IWM 判例，重写会全没。合并脚本只能做文本追加，且必须给含 `: ` 的值加引号（否则 `ScannerError: mapping values are not allowed here`）。
3. **Vite 的文件监听会崩**。用脚本批量改 `data/*.yaml` 时报 `EBUSY: resource busy or locked, watch '...tmp'`，dev server 整个挂掉。已在 `astro.config.mjs` 的 `watch.ignored` 里加了 `**/*.tmp` 与 `**/*.bak*`，但偶发仍会崩——遇到就重启 `npm run dev`。
4. **dev server 会锁 `data/` 与 `src/` 的文件句柄**，导致 `edit` 报 `ReplaceFileW EIO (Win32 32)`。先停 dev 再改，或同一文件连续两次失败就说明是占用，**不要重试第三次**。
5. **PowerShell 里 `python -c "..."` 带中文或嵌套引号极易被拆碎**（`+ CategoryInfo : ObjectNotFound: (tl:String)`）。超过两行的 python 一律写成 `work/*.py` 文件再跑。
6. **Chrome headless 截图输出路径不能含空格**。项目路径是 `D:\deepseek harness\...`，会报「系统找不到指定的路径 (0x3)」。先写 `$env:TEMP\` 再拷回来。
7. **`git` 在本机不可用**。批量改文件用 python 脚本，先 `assert s.count(old) == 1` 再替换。
